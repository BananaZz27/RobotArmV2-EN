## Safety rules (real arm)
- **Ask the user before every arm motion** and have them support the arm · first runs at low speed, short distances
- Check supply ≥ 6 V and all 4 servos answering before and after moving · with the arm stretched far forward the supply sags and the shoulder cannot lift (not enough current)
- COM11 can be open in only one program at a time · torque off = the arm goes limp immediately
- The user prefers the assistant to run commands step by step and report results over clicking through the GUI

## Code
- Calibration lives only in `src/config.py` (J5 head removed `used=False`, d5 = 50 mm)
- `qt_app.py` (PyQt6, ws-control style) + `viewer3d.py` (PyVista) → `motion.py` (Mover, no hardware) → `driver.py` (40 ms thread) → `link.py` (DirectLink / SimLink)
- Windows region set to Thai → `qt_app.main()` forces QLocale en-US, otherwise spin boxes show Thai digits
- Tests: `cd src && ../.venv/Scripts/python.exe -m pytest -q`
- Windows: the 40 ms thread actually ticks every 27–52 ms → the driver sends "the pose STREAM_MS (80 ms) ahead + time 80 ms" (`Mover.peek`), otherwise jog is jerky (measured on the real arm 2026-11-19: elbow speed swing ±10.8 → ±5.8 °/s, lag 4.4° → 2.5°)
- Maths explained: `docs/explain.md` (charts generated by `docs/make_charts.py`)
